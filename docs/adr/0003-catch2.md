# 0003 — Use Catch2 for Unit Testing

## Status

Proposed

## Context

We develop the raytracer using strict Test-Driven Development (TDD). Because C++ is a new language for part of the team and ray tracing relies heavily on floating-point vector maths, we need a unit testing framework that is readable, expressive, and handles floating-point tolerances cleanly.

Alternatives considered:

- **GoogleTest** — widely used in industry, but its macro syntax (`EXPECT_DOUBLE_EQ`, `TEST`) is more verbose than plain C++ expressions.
- **doctest** — fast compile times and similar syntax to Catch2, but has a smaller ecosystem and fewer built-in matchers.
- **Boost.Test** — mature, but pulls in the heavy Boost dependency.

## Decision

Use Catch2 v3 (`v3.7.1`), fetched automatically via CMake `FetchContent`. Write tests in `tests/` using `TEST_CASE` and `REQUIRE` / `CHECK` macros, with `Catch::Approx` for floating-point tolerance checks, linking against `Catch2::Catch2WithMain`.

## Consequences

**Positive:**
- Test cases read like specifications (`TEST_CASE("description", "[tag]")`) and assertions use standard C++ comparisons inside `REQUIRE(...)`.
- `Catch::Approx` simplifies floating-point comparisons (`double` / `float` with epsilon tolerance).
- Linking `Catch2::Catch2WithMain` removes the need to maintain a custom `main()` function for the test runner.

**Negative:**
- Catch2 v3 is compiled as a static library, which adds time to the initial build after a clean.
- Tests are coupled to Catch2 macros; switching frameworks later would require rewriting test files.
